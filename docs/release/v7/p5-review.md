# P5 portable projections independent review

Date: 2026-09-17

Base reviewed: `cc08b4f696b6226e88cca1f83104ce870dd62ae6`

Status: **not accepted**. Canonical event replay, format-1 compatibility, and event-derived migration-map reconstruction pass focused review, but the format-2 transport and optional-vector lifecycle still have six material correctness, isolation, and resource-bound failures.

This is a bounded P5 review. It does not accept whole-P5, the concurrent P1/P3/P6 work, or the final release.

## Findings

### HIGH — Portable vector transfer bypasses the disabled local capability profile

Affected components:

- `daem0nmcp/api/v7/operations.py:162-174`, `944-1006`, `1102-1196`
- `daem0nmcp/api/v7/portable_projections.py:240-368`, `1017-1046`
- `daem0nmcp/api/v7/production.py:643-647`, `752-760`

Production passes the capability registry into `CoreOperationDependencies`, but export and import never consult `projection_capability_statuses`. `workspace_export(include_vectors=True)` calls `_vector_snapshot`, which imports/creates a Qdrant client from settings whenever a dense manifest exists. Import similarly creates Qdrant after checking only model ID and dimension. An installed/configured provider is therefore used even when the `local` profile is disabled.

This explains why the earlier MCP probe could export vectors without `DAEM0NMCP_LOCAL_ENABLED=true`; it exercised an authorization/capability bypass rather than proving the disabled-profile contract. Main-thread optional-runtime preload gating does not close the direct operation path.

Why it matters: disabled optional capabilities must not import native providers, open provider storage/network connections, or mutate external collections. The current path violates explicit deployment configuration and can unexpectedly disclose vector payloads to a configured endpoint.

Remediation: require `projection_capability_statuses["local"] == "ready"` before any vector snapshot or candidate operation, before importing or constructing the Qdrant client. Export should return a stable actionable capability error. Import should either reject vector activation or return the reviewed rebuild-required diagnostic without external writes. Add production tests with the package installed and Qdrant settings present while the local profile is disabled, asserting the client factory is never called.

### HIGH — The full manifest makes format-2 pages exceed the transport bound

Affected components:

- `daem0nmcp/api/v7/portable_projections.py:371-444`, `559-631`, `642-701`
- `daem0nmcp/api/v7/tools.py:822-888`, `1558-1574`

Page content is capped at 850,000 bytes, but every response and every import request also embeds `manifest.pages`, containing metadata for every page. The manifest has no byte or entry bound tied to the MCP response ceiling. The caller may choose the allowed 65,536-byte page size, while a session may hold 4 GiB and the schema permits up to 1,000,000 pages.

A deterministic size probe built only the metadata generated by the implementation:

```text
5,053 pages  -> 777,271-byte manifest
65,536 pages -> 10,147,190-byte manifest
```

At the minimum allowed page size, the manifest alone is roughly five times the 2 MiB transport ceiling before adding page content and response wrapping. It can also exceed recursive JSON item limits. Large exports therefore cannot be retrieved or re-imported through the advertised bounded protocol.

Remediation: keep the immutable manifest server-side and return a compact, hash-bound session header plus metadata for the current page, or page the manifest itself. Bind each page to a stable manifest root/Merkle root without echoing the complete page table. Enforce the serialized size of the complete RPC result, not only `content`.

### HIGH — Export session quota, interruption recovery, and cancellation do not bound retained data

Affected components:

- `daem0nmcp/api/v7/operations.py:256-280`, `944-1006`, `1604-1610`
- `daem0nmcp/api/v7/portable_projections.py:112-127`, `447-639`, `704-867`

The export path checks quota before reserving a database row, creates a random directory and a full SQLite backup, writes every page, and inserts the session only after the build completes. Consequences:

- Concurrent builders can all pass the same pre-build count/byte check and exceed the four-session quota.
- A process exit before the final insert leaves an untracked random session directory that `_clean_expired` can never discover.
- `total_bytes` counts page bodies only. The retained full SQLite snapshot and import validation/section files are omitted.
- Successful import sessions are excluded from the live import quota even though their staged and validation files remain until expiry.
- Export uses `_run_blocking`. If cancellation lands after publication, it waits for completion and then raises `CancelledError`, hiding the random session ID while leaving a ready session that consumes quota for 24 hours.

The physical-accounting probe on one tiny event observed:

```text
tracked_total_bytes=1,917
physical_file_bytes=640,893
source.snapshot.db=638,976
```

A cancellation-at-publication probe observed:

```text
caller_received_cancelled
one random export session remained status='ready'
```

Four such cancellations can exhaust the advertised workspace session quota without giving the caller an ID it can resume.

Remediation: transactionally reserve a `building` row and quota before creating files, account for all physical files or promptly delete the source snapshot after page publication, include every non-expired retained session in aggregate accounting, and recover/remove database rows and orphan directories after interruption. Make export cancellation-aware; before publication remove the reservation/files, and after publication return the committed first-page receipt rather than report cancellation.

### HIGH — Concurrent finalization can delete the winning active Qdrant collection

Affected components:

- `daem0nmcp/api/v7/operations.py:1147-1218`, `1267-1372`
- `daem0nmcp/api/v7/portable_projections.py:1017-1216`, `1219-1351`

An import session is never atomically claimed as `finalizing`. Two requests with the same session and idempotency key can both pass the receipt check and prepare a candidate before either begins the canonical SQLite transaction. Candidate collection names and `validated-vectors.db` names are deterministic and shared. One request may commit the active manifest; the losing request then fails its generation/validation check and unconditionally calls `discard()`, deleting the collection now referenced by the winner.

A sequentialized probe of this exact concurrency window prepared two candidates before activation, committed the first, then ran the loser cleanup:

```text
loser_failure='OperationalError'
active_collection_exists_after_loser_cleanup=False
```

The canonical database reports an active dense generation whose external collection no longer exists.

Remediation: claim the session/idempotency operation under `BEGIN IMMEDIATE` before any candidate build, persist a finalization owner/lease, and make other callers wait for or return the durable receipt. Give each attempt a unique candidate collection and validation path. Cleanup must delete only a collection owned by that failed attempt and must recheck that no active manifest references it.

### HIGH — Vector activation after merge publishes a projection for the wrong canonical root

Affected components:

- `daem0nmcp/api/v7/operations.py:1219-1290`
- `daem0nmcp/api/v7/portable_projections.py:1219-1351`

With `merge=True`, the target may already contain canonical events and records absent from the imported snapshot. Activation validates that every imported point still references a live record, but it never proves the post-replay target event count/root equals the vector snapshot's source count/root or that all eligible target records have a vector. It then publishes the imported source root as the active dense manifest.

A deterministic merge probe used a one-event/one-vector source and a target with one additional memory. Import returned `succeeded`, then showed:

```text
active manifest event_count=1, row_count=1, status='active'
actual canonical event_count=2
actual_root_matches_manifest=False
dense_refs=1
```

The operation therefore makes a known-stale partial dense projection active.

Remediation: immediately before activation compute the target canonical event count/root under the same SQLite transaction and require an exact match to the candidate snapshot. If merge produces a superset, do not activate imported vectors; retain the previous valid generation and return `VECTOR_REBUILD_REQUIRED`. Validate expected dense-record coverage as well as the one-way point-to-record binding.

### MEDIUM — Vector metadata compatibility is only partially validated

Affected component: `daem0nmcp/api/v7/portable_projections.py:1025-1057`, `1171-1185`, `1293-1300`.

Import compares only `model_id` and `dimension`. It accepts an unsupported vector `schema_version` and an arbitrary `provider_key`, then stores that provider in active manifest details and dense references. Runtime dense retrieval uses the configured provider key `qdrant`, so a foreign provider value can make an apparently active import invisible to retrieval. No full builder/encoder contract is carried or checked.

A direct candidate probe was accepted with:

```text
schema_version=999
provider_key='foreign-provider'
diagnostic=None
```

Remediation: define and validate the complete portable vector contract before any external write: supported schema version, configured provider key, positive source generation, exact model/dimension, distance, builder version, and any encoder contract fields that affect vector semantics. Unsupported semantics should produce `VECTOR_REBUILD_REQUIRED`; malformed metadata should produce `IMPORT_INVALID`.

## Accepted behavior in the reviewed slice

No material issue was found in these areas:

- Format-1 import remains identity-preserving and atomically replays the original authoritative event envelopes.
- Format-2 page hashes, section hashes, event root, stream chains, causation edges, and semantic memory dependencies are validated before canonical commit. Facts and relationships with equal timestamps replay in deterministic dependency order.
- Foreign import does not trust the origin-local HMAC export cursor; page/manifest hashes form the portable boundary.
- Canonical replay runs under one SQLite transaction. Tamper, conflict, pre-commit cancellation, and legacy-projection mismatch roll back authoritative changes and the job receipt.
- Migration maps are reconstructed from verified `actor_type='migration'` events, their exact lossless `legacy` payloads, correlation run IDs, target streams, and imported event IDs. The real v6 fixture imports six events/five mapping kinds and passes `verify_v7`; fake projection-only claims are no longer accepted.
- Vector upload uses an isolated collection, bounded batches/scrolls, deterministic point IDs, safe payloads, finite dimensions, exact payload comparison, and cosine-normalized float tolerance before activation.
- Migration 24 gives sessions/pages typed keys, status, hashes, counts, expiry, and foreign-key ownership.
