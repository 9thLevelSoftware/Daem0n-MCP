`execute.before` carries `tool`, `sessionID`, `agent`, `messageID`, `id`, and
`input`. The after hook exposes a completed/error union. Native V2 write/edit
arguments use `path`, with `content` or `oldString`/`newString`, respectively.
Code Mode inner tools can share the outer execution ID, so an edit binding must
also include the exact tool and arguments. A rejection thrown by a before hook
has no corresponding after event; it cannot be treated as a successful edit.

The direct probe's first warnings read was unavailable before any briefing.
This follows the server's resource authorization contract:
`ResourceCommunionAuthorizer` requires an already-briefed session. Diagnostic
`system_health` and resource discovery/reads do not trigger automatic briefing.
The subsequent `memory_store` automatically briefed the same MCP session, and
the resource read then succeeded. This observation is not a projection-recovery
failure and does not establish that an empty resource is available before brief.

The first provisional Code Mode fixture lacked its own Git root, so V2 found
the enclosing repository as its project. The later direct fixture initializes
an empty Git root and records its own project root in the setup event. Native
logs also show that V2 scans ancestor plugin directories even across this Git
boundary: it attempted the repository's V1 plugin and rejected its incompatible
export. Final Windows fixtures therefore live outside the repository ancestry,
with independent Git roots and private HOME directories, without commits.
